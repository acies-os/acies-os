# Raspberry Pi Setup

Repeat this page for every sensor node. The examples use node `rs1`; substitute each node's own
name.

On the Pi you only install Docker, a checkout of `acies-os` (for compose files and recipes), and
the directories for data and weights. All Python code ships inside the `acies-pi` image, which
you build on the edge server and the Pi pulls.

## 1. Flash the OS

1. Install [Raspberry Pi Imager](https://www.raspberrypi.com/software/).
2. Choose **Raspberry Pi OS Lite (64-bit)**. The image is `linux/arm64`, so a 32-bit OS will not work.
3. Before writing, open **Edit settings** (OS customisation) and fill in the three tabs.

**General.** Set the hostname to the node name (`rs1`, `rs2`, …). This hostname becomes the
node's mDNS name `rs1.local`, and by default also its Acies namespace. Set a username (the
reference fleet uses `myshake`) and password, the Wi-Fi SSID and password of the network the
edge server will be on, your Wi-Fi country, and time zone **Etc/UTC**.

```{image} ../images/rpi_imager_1.png
:width: 420px
:alt: Raspberry Pi Imager, General tab
```

**Services.** Enable SSH. Either keep password authentication and run `ssh-copy-id` later, or
paste the edge server's `~/.ssh/id_ed25519_pi.pub` here and choose *public-key only*.

```{image} ../images/rpi_imager_2.png
:width: 420px
:alt: Raspberry Pi Imager, Services tab
```

**Options.** Defaults are fine.

```{image} ../images/rpi_imager_3.png
:width: 420px
:alt: Raspberry Pi Imager, Options tab
```

4. Write the card, insert it, connect the Raspberry Shake board, the USB microphone array, and
   the antenna, then power on. The first boot takes a few minutes.

:::{note}
In the field the Pis join whatever Wi-Fi you configured here. That is often a hotspot
from the edge laptop or a travel router. Use the same SSID and password on every node so you can
move them between sites without reflashing. See [Network configuration](05-network.md).
:::

## 2. First login and base packages

From the edge server (with the SSH alias from {ref}`Access <sec-ssh-to-pi>`):

```bash
ssh rs1
```

On the Pi:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y git just rsync curl jq alsa-utils
uname -m          # must print aarch64
```

## 3. Install Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
exit              # log out and back in so the group change applies
ssh rs1 docker run --rm hello-world
```

## 4. Enable the sensor interfaces

**Geophone (Raspberry Shake, serial).** `acies-geo` reads `/dev/serial0` at 230400 baud.
Enable the UART and disable the serial login console:

```bash
sudo raspi-config nonint do_serial_hw 0      # enable serial hardware
sudo raspi-config nonint do_serial_cons 1    # disable login shell on serial
sudo reboot
ls -l /dev/serial0                           # after reboot: symlink to ttyAMA0 / ttyS0
```

**Microphone array (USB).** Check that ALSA sees the device:

```bash
arecord -l                                   # look for the array, e.g. "ArrayUAC10"
```

`just record` records a 40-second, 6-channel test clip to `/data/alsa-test.wav`.

## 5. Create the data and model directories

The compose files mount these host paths into the containers:

```bash
sudo mkdir -p /data /model /ws/acies
sudo chown -R "$USER":"$USER" /data /model /ws/acies
```

| Host path | Mounted as | Contents |
| --- | --- | --- |
| `/model` | `/model` (read-only) | Model weight files (`*.pt`) |
| `/data` | `/data` | Live recordings; replay scenes such as `/data/2024-03-29-ICT/`, `/data/audrok/` |
| `~/.acies` | `/root/.acies` | Logs and service state |

## 6. Clone `acies-os` on the Pi

The Pi needs the repository for `docker/pi*.yml` and `just/pi.just`. Connect with agent
forwarding so the private clone uses your key (see {ref}`Access <sec-pi-github-access>`):

```bash
ssh -A rs1
cd /ws/acies
git clone git@github.com:acies-os/acies-os.git
cd acies-os && git checkout mono-mobicom-model-sep
```

The path `/ws/acies/acies-os` is what the edge recipes and `scripts/update-pis.sh` expect. If
you use a different path, set `PI_APP_DIR` in the edge `.env`.

## 7. Create the Pi `.env`

```bash
cd /ws/acies/acies-os
cp docker/.env.pi.example .env
```

Edit:

```bash
ACIES_NAMESPACE=rs1                       # this node's name; must match the site config
ZENOH_BRIDGE=tcp/<EDGE_LAN_IP>:7500       # edge zenohd LAN endpoint (= edge ZENOH_LISTEN port)
ZENOH_CONNECT=tcp/127.0.0.1:7501          # leave as is
MODEL_DIR=/model
# weight filenames and labels: keep identical to the edge .env
```

For the tabletop demo (scenario 3), also uncomment the replay block:

```bash
SCENE=2024-03-29-ICT
RUN=2
NODE=rs1          # which recorded node to replay; defaults to ACIES_NAMESPACE
DRONE_SCENE=audrok
DRONE_RUN=1
DRONE_NODE=rs1
```

:::{warning}
`ZENOH_BRIDGE` is passed directly to `zenohd --connect`, so it must be the bare endpoint
`tcp/IP:PORT`. Some comments in `docker/pi.yml` show `"--connect tcp/…"`. Don't include
`--connect` in the value.
:::

## 8. Trust the edge registry

Docker refuses to pull from a plain-HTTP registry unless you allow it. **From the edge server**,
run once per Pi:

```bash
just registry-trust rs1
```

This **overwrites** `/etc/docker/daemon.json` on the Pi with
`{"insecure-registries":["<REGISTRY_EXTERNAL>"]}` and restarts Docker. If you keep other
settings in that file, add the entry by hand instead.

## 9. Pull the image

After you've built and pushed the Pi image ([Build and deploy](06-build-and-run.md)), run from the edge server:

```bash
just deploy-pi                 # pulls <REGISTRY_EXTERNAL>/acies-pi:latest on all PI_HOSTS and tags it acies-pi:latest
ssh rs1 docker images | grep acies-pi
```

## 10. Copy weights (and replay data)

From the edge server:

```bash
just upload-model ~/acies/models/Parkland_ict2024_encoder.pt     # one file to /model on every PI_HOSTS
# or everything at once, including drone replay data and .env keys:
scripts/update-pis.sh --dry-run
scripts/update-pis.sh
```

See [Data and model weights](07-data-and-weights.md) for which files each node needs.

## Checklist

- [ ] `ssh rs1 uname -m` prints `aarch64`.
- [ ] `ssh rs1 docker ps` works without `sudo`.
- [ ] `/dev/serial0` exists, and `arecord -l` lists the microphone array.
- [ ] `/data`, `/model`, and `/ws/acies/acies-os` exist and belong to your user.
- [ ] `/ws/acies/acies-os/.env` has the correct `ACIES_NAMESPACE` and `ZENOH_BRIDGE`.
- [ ] `docker images` on the Pi shows `acies-pi:latest`.
- [ ] `/model` contains every weight file named in the Pi `.env`.
